# 测试驱动开发（TDD）

## 铁律

没有失败的测试，就不写产品代码。先写了代码？删掉，从测试重来。
（违反规则的字面，就是违反规则的精神。）

## 红-绿-重构

1. **RED**：写一个最小的失败测试，描述「应该发生什么」。
2. **看它失败**：运行测试，确认它失败、且因「功能缺失」而非笔误失败。
3. **GREEN**：写刚好让它通过的最小代码，不过度设计。
4. **看它通过**：运行测试，确认通过、且其它测试不被破坏、输出干净。
5. **REFACTOR**：在保持全绿的前提下清理重复、改善命名。

## 常见借口与现实

- 「太简单不用测」→ 简单代码也会坏，测试只要 30 秒。
- 「先写完再补测试」→ 事后测试立刻通过，证明不了任何东西。
- 「手动测过了」→ 临时手测无记录、不可重放。

## 原则

一次测一个行为；测真实行为而非 mock；边界与错误路径都要覆盖。
