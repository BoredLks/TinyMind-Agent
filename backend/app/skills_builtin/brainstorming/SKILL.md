# 头脑风暴：把想法变成设计

在写任何代码前，先弄清用户真正想要什么。

## 流程

1. 先了解项目现状（看相关文件、最近改动）。
2. 一次只问一个问题，澄清目的、约束、成功标准；优先用选择题。
3. 提出 2–3 个不同方案，附权衡与你的推荐（先说推荐项及理由）。
4. 分段呈现设计，每段都征求用户确认后再继续。
5. 用户认可后，把设计写成文档，再进入「写计划」。

## 硬门禁

未经用户确认设计，不要写代码、不要搭脚手架——再「简单」的项目也走这个流程。
简单项目恰恰是未经审视的假设最容易造成返工的地方。

## 原则

- YAGNI：从设计里砍掉不必要的功能。
- 一次一问，增量确认。
- 随时可以回退澄清。
